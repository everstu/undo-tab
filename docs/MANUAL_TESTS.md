## 2. 手工验收前置

1. 使用**常规安装版 Chrome**（不是 CDP 自动化加载），在 `chrome://extensions` 加载项目根目录（包含 manifest.json 的目录），记录 Chrome 版本。
2. 在扩展详情页开启“允许在无痕模式下运行”。
3. 准备本地测试站点或 `example.com`；**不要使用真实无痕网址**做记录或截图。
4. 在扩展页打开 Service Worker 的 DevTools，必要时执行 `chrome.storage.session.get(null)` / `chrome.storage.local.get(null)` 辅助核对；不要把含真实无痕 URL 的内容粘贴到报告。
5. 每项记录“通过 / 失败 / 未执行”，失败需附最小复现步骤。

- [x] **N4 query/fragment 区分**：分别打开 `/a`、`/a?x=1`、`/a#one` 并关闭，得到三条不同记录；`/a?x=1&y=2` 与 `/a?y=2&x=1` 也不同。
- [x] **N5 搜索与切换**：搜索只过滤当前视图；切换“历史记录”再切回，搜索词保留、页码回第一页、滚动回顶部；关闭再打开弹窗恢复空搜索。

## 5. 无痕会话（I）

> 以下必须在真实无痕窗口执行；自动化跳过不能替代。

- [x] **I1 上下文隔离**：打开无痕窗口，点击工具栏图标；只有“最近关闭 / 历史记录”，不出现普通最近关闭、普通历史或“在 Chrome 中管理历史”入口。
- [x] **I2 访问即出现**：在无痕窗口访问两个页面，**先不关闭**，打开弹窗“历史记录”，两条立即存在；最近关闭仍为空。
- [x] **I3 导航计数**：刷新、前进/后退、SPA pushState/replaceState、hash 变化各验收一次：同 URL 访问次数增加、`lastVisitedAt` 更新并置顶；一次导航只累计一次；子框架 iframe 不进入列表。
- [x] **I4 标题/favicon 补齐**：页面标题晚到时，历史条目标题更新；标题变化本身不增加访问次数；不同标签/下一页面的标题不会补给上一页面。
- [x] **I5 多无痕窗口**：打开两个无痕窗口，各产生最近关闭/访问；关闭其中一个，另一个窗口的弹窗中两个列表仍保留；普通数据不受影响。
- [x] **I6 最后一个窗口清空**：关闭最后一个无痕窗口（不是最小化/失焦/关弹窗）；重新打开无痕窗口，两个列表均为空；DevTools 中 `incognito.meta` 应为已结束状态，`incognito.recent` / `incognito.history` / `incognito.liveTabs` 均为空数组；普通最近关闭/设置不变。
- [x] **I7 旧记录不可恢复**：在 I6 前打开弹窗并保持，关闭最后窗口后弹窗应显示会话结束/空；不能通过旧行恢复出无痕标签页。
- [x] **I8 权限撤销**：在扩展详情页关闭“允许在无痕模式下运行”，重新打开无痕窗口；扩展不显示旧数据、不再采集；普通窗口记录仍可用。
- [x] **I9 同 URL 分域**：同一 URL 在普通和无痕各关闭一次，两个模式各自一条，互不合并、互不淘汰。
- [x] **I10 独立上限**（10–1000 规则后需重测）：普通最近关闭设 12、普通历史展示设 13、无痕最近关闭设 10、无痕历史设 11；分别产生更多不同 URL，四个列表分别保留或展示最新的 12/13/10/11 条，互不影响。后台休眠后的新增和失败补写仍按对应上限裁剪。
- [x] **I11 清空本次记录**：无痕设置“清空本次记录”确认后，两个列表与 pending 清空，会话仍有效；之后新访问/关闭可以继续记录；普通数据不变。
- [x] **I12 单删/分视图清空**：无痕最近关闭单删/清空不影响访问历史；访问历史单删/清空不影响最近关闭。
- [x] **I13 worker 休眠**：有无痕窗口时等待 Service Worker 休眠（或 `chrome://serviceworker-internals` 停止），再打开弹窗/关闭标签：数据保留且不产生虚假访问；关闭最后一个无痕窗口后再唤醒，旧数据不得复活。
- [x] **I14 事件竞态**：在关闭最后一个无痕窗口的同时关闭标签、快速导航或重开新无痕窗口；旧会话的关闭/导航/标题结果不得写入新会话；新会话从空数据开始。
- [x] **I15 无普通窗口**：只保留无痕窗口时，普通记录仍持久；关闭最后无痕窗口后没有可读取的旧无痕会话。

## 6. 设置与宽度（S）

- [x] **S1 宽度**：360、440、800 各保存一次，弹窗立即生效；重开弹窗仍生效；恢复默认回到 440；普通与无痕共用同一宽度。
- [x] **S2 独立上限**：两种模式的设置均有最近关闭与历史两个输入框、各自保存。改最近关闭不改历史，反之亦然；关闭再打开设置仍保留两个不同值。
- [x] **S3 裁剪确认**：下调会删除自有集合数据时先确认；无痕确认只列当前修改的列表及删除条数，说明另一列表不受影响。取消不修改；确认后只裁剪对应集合。普通历史展示上限直接保存，不出现删除确认，不裁剪最近关闭。
- [x] **S4 Chrome 历史**：任何上限/清空操作都不删除或缩减 Chrome 历史。
- [x] **S5 非法输入**（10–1000 规则后需重测）：小数（如 12.5）、空值、非数字被拒绝并显示 10–1000 / 360–800 范围提示，原设置不变。
- [x] **S6 设置范围说明**：普通设置说明最近关闭保留上限与历史展示上限独立、展示上限不删除 Chrome 历史；无痕设置显示两个集合并列说明；普通窗口不显示无痕设置块。
- [x] **S7 默认条数**：新安装的两种模式共四项上限均为 100；已有合法上限和宽度保留，缺少普通历史上限时继承升级前的普通上限。
- [x] **S8 越界收紧**：四个条数输入框分别输入 0、3、-5 → 输入框变为 10、保存为 10，并以提醒色提示“记录条数最小为 10，已按 10 条保存”；输入 1001、5000 → 保存为 1000 并提示“最大为 1000”。若收紧后的值会删除记录，确认框先说明“将按 10 条保存”。宽度输入 300 → 360px、1200 → 800px 并提示；弹窗高度保持 580px。普通与无痕窗口各验收一次。

## 7. 迁移与升级（M）

1. 在旧版本（schema 1）产生若干普通/无痕关闭记录，并修改宽度/上限。
2. 升级到 0.2.0，重新加载扩展（或重启浏览器）。
3. 检查：

- [x] **M1** 普通记录保留，并按完整 URL 去重、保留最新关闭元数据；保留宽度，旧 maxRecords 迁移到 `normal.maxRecords`、`normal.historyMaxRecords`、`incognito.recentMaxRecords`、`incognito.historyMaxRecords`。旧 schema 2 缺少普通历史上限时继承原普通上限，无痕共用 maxRecords 同样回填为两个独立值；再次初始化不改已保存值。
- [x] **M2** 旧 `history.records` 中的无痕记录不再出现，`storage.local` 不再包含旧无痕 URL；旧 `live.tabs` 已删除。
- [x] **M3** `settings.schemaVersion === 2`；旧普通 pendingClose 迁移后仍可补写，且不会重复。
- [x] **M4** 再次重启/重新加载，普通记录不丢失、不重复；旧 key 不会重新出现。
- [x] **M5** 迁移失败（可临时把 `storage.local` 配额占满）时显示错误/重试，不回退显示旧混合数组；释放空间后重试成功。
- [x] **M6 旧越界上限**：在旧版本把普通最近关闭上限设为大于 1000（或在 DevTools 将 `settings.normal.maxRecords` 改为 5000）并准备超过 1000 条普通最近关闭，另设一项小于 10、宽度大于 800；重新加载扩展后，设置分别变为 1000 / 10 / 800，普通最近关闭立即只剩最新 1000 条（页脚 `共 1000 条 · 上限 1000`），Chrome 历史不受影响。

## 8. pending 与清空回归（P）

- [x] **P1 旧 pending 不复活**：用 DevTools 暂时占满 `storage.local` 配额，关闭一个标签使写入失败（页脚出现“有 1 条…尚未保存”）；释放空间前清空普通最近关闭；恢复空间并等待补写/重启 worker，旧记录不得重新出现。
- [x] **P2 旧事件不覆盖新事件**：在 P1 基础上让同一 URL 先失败、后成功关闭；旧事件晚补写时，标题/时间/置顶顺序仍为较新一次。
- [x] **P3 删除后 pending 取消**：单删某 URL 时存在同 URL pending，删除后补写不得恢复；之后真实关闭该 URL 仍可生成新条目。

- [x] **R2** 无痕窗口点击工具栏图标：只显示本次无痕数据；普通历史不泄漏。
- [x] **R3** 关闭弹窗（不是关闭窗口）不触发无痕清理；只有关闭最后一个无痕窗口才清理。
