## 2. 手工验收前置

1. 使用**常规安装版 Chrome**（不是 CDP 自动化加载），在 `chrome://extensions` 加载项目根目录（包含 manifest.json 的目录），记录 Chrome 版本。
2. 在扩展详情页开启“允许在无痕模式下运行”。
3. 准备本地测试站点或 `example.com`；**不要使用真实无痕网址**做记录或截图。
4. 在扩展页打开 Service Worker 的 DevTools，必要时执行 `chrome.storage.session.get(null)` / `chrome.storage.local.get(null)` 辅助核对；不要把含真实无痕 URL 的内容粘贴到报告。
5. 每项记录“通过 / 失败 / 未执行”，失败需附最小复现步骤。

## 3. 普通弹窗与最近关闭（N）

- [ ] **N1 视图与来源**：普通窗口打开弹窗，仅有“最近关闭 / 历史记录”，无普通/无痕切换、无行内来源徽标；默认最近关闭、空搜索。
- [ ] **N2 关闭记录**：打开两个 http/https 页面并关闭，最近关闭出现两条；关闭时间较新的在上；相对时间正确。
- [ ] **N3 同 URL 去重**：重新打开同一 URL 再关闭，仍只有一条，标题/时间更新并置顶。
- [ ] **N4 query/fragment 区分**：分别打开 `/a`、`/a?x=1`、`/a#one` 并关闭，得到三条不同记录；`/a?x=1&y=2` 与 `/a?y=2&x=1` 也不同。
- [ ] **N5 搜索与切换**：搜索只过滤当前视图；切换“历史记录”再切回，搜索词保留、页码回第一页、滚动回顶部；关闭再打开弹窗恢复空搜索。
- [ ] **N6 分页**：准备 51 条以上最近关闭，第一页 50 条，页码 `1/2`；第二页 1 条；删除/去重置顶后页码收敛。
- [ ] **N7 页脚**：无搜索显示 `共 N 条 · 上限 M`；搜索显示 `匹配 N 条`；只统计普通最近关闭。
- [ ] **N8 打开**：点击记录在普通窗口打开 URL；来源窗口已关闭时仍能回普通窗口，没有普通窗口时新建普通窗口。
- [ ] **N9 单删/清空**：删除按钮只删该条并刷新；清空普通最近关闭后列表 0 条，Chrome 历史不受影响。

## 5. 无痕会话（I）

> 以下必须在真实无痕窗口执行；自动化跳过不能替代。

- [ ] **I1 上下文隔离**：打开无痕窗口，点击工具栏图标；只有“最近关闭 / 历史记录”，不出现普通最近关闭、普通历史或“在 Chrome 中管理历史”入口。
- [ ] **I2 访问即出现**：在无痕窗口访问两个页面，**先不关闭**，打开弹窗“历史记录”，两条立即存在；最近关闭仍为空。
- [ ] **I3 导航计数**：刷新、前进/后退、SPA pushState/replaceState、hash 变化各验收一次：同 URL 访问次数增加、`lastVisitedAt` 更新并置顶；一次导航只累计一次；子框架 iframe 不进入列表。
- [ ] **I4 标题/favicon 补齐**：页面标题晚到时，历史条目标题更新；标题变化本身不增加访问次数；不同标签/下一页面的标题不会补给上一页面。
- [ ] **I5 多无痕窗口**：打开两个无痕窗口，各产生最近关闭/访问；关闭其中一个，另一个窗口的弹窗中两个列表仍保留；普通数据不受影响。
- [ ] **I6 最后一个窗口清空**：关闭最后一个无痕窗口（不是最小化/失焦/关弹窗）；重新打开无痕窗口，两个列表均为空；DevTools 中 `incognito.state` 应为已结束空状态；普通最近关闭/设置不变。
- [ ] **I7 旧记录不可恢复**：在 I6 前打开弹窗并保持，关闭最后窗口后弹窗应显示会话结束/空；不能通过旧行恢复出无痕标签页。
- [ ] **I8 权限撤销**：在扩展详情页关闭“允许在无痕模式下运行”，重新打开无痕窗口；扩展不显示旧数据、不再采集；普通窗口记录仍可用。
- [ ] **I9 同 URL 分域**：同一 URL 在普通和无痕各关闭一次，两个模式各自一条，互不合并、互不淘汰。
- [ ] **I10 独立上限**：普通上限设 4、无痕最近关闭设 2、无痕历史设 3；分别产生更多不同 URL，三个列表保留最新的 4/2/3 条，互不影响。后台休眠后的新增和失败补写仍按对应上限裁剪。
- [ ] **I11 清空本次记录**：无痕设置“清空本次记录”确认后，两个列表与 pending 清空，会话仍有效；之后新访问/关闭可以继续记录；普通数据不变。
- [ ] **I12 单删/分视图清空**：无痕最近关闭单删/清空不影响访问历史；访问历史单删/清空不影响最近关闭。
- [ ] **I13 worker 休眠**：有无痕窗口时等待 Service Worker 休眠（或 `chrome://serviceworker-internals` 停止），再打开弹窗/关闭标签：数据保留且不产生虚假访问；关闭最后一个无痕窗口后再唤醒，旧数据不得复活。
- [ ] **I14 事件竞态**：在关闭最后一个无痕窗口的同时关闭标签、快速导航或重开新无痕窗口；旧会话的关闭/导航/标题结果不得写入新会话；新会话从空数据开始。
- [ ] **I15 无普通窗口**：只保留无痕窗口时，普通记录仍持久；关闭最后无痕窗口后没有可读取的旧无痕会话。

## 6. 设置与宽度（S）

- [ ] **S1 宽度**：360、440、800 各保存一次，弹窗立即生效；重开弹窗仍生效；恢复默认回到 440；普通与无痕共用同一宽度。
- [ ] **S2 独立上限**：普通窗口只改普通上限；无痕设置有两个输入框、各自保存。改最近关闭不改历史，反之亦然；关闭再打开设置仍保留两个不同值。
- [ ] **S3 裁剪确认**：下调会删除数据时先确认；无痕确认只列当前修改的列表及删除条数，说明另一列表不受影响。取消不修改；确认后只裁剪对应集合。
- [ ] **S4 Chrome 历史**：任何上限/清空操作都不删除或缩减 Chrome 历史。
- [ ] **S5 非法输入**：0、10001、小数、空值被拒绝并显示 1–10000/360–800 范围提示，原设置不变。
- [ ] **S6 设置范围说明**：普通设置显示“上限只作用于普通最近关闭”；无痕设置显示两个集合并列说明；普通窗口不显示无痕设置块。

## 7. 迁移与升级（M）

1. 在旧版本（schema 1）产生若干普通/无痕关闭记录，并修改宽度/上限。
2. 升级到 0.2.0，重新加载扩展（或重启浏览器）。
3. 检查：

- [ ] **M1** 普通记录保留，并按完整 URL 去重、保留最新关闭元数据；保留宽度，旧 maxRecords 迁移到 `normal.maxRecords`、`incognito.recentMaxRecords`、`incognito.historyMaxRecords`。旧 schema 2 的无痕共用 maxRecords 同样回填为两个独立值。
- [ ] **M2** 旧 `history.records` 中的无痕记录不再出现，`storage.local` 不再包含旧无痕 URL；旧 `live.tabs` 已删除。
- [ ] **M3** `settings.schemaVersion === 2`；旧普通 pendingClose 迁移后仍可补写，且不会重复。
- [ ] **M4** 再次重启/重新加载，普通记录不丢失、不重复；旧 key 不会重新出现。
- [ ] **M5** 迁移失败（可临时把 `storage.local` 配额占满）时显示错误/重试，不回退显示旧混合数组；释放空间后重试成功。

## 8. pending 与清空回归（P）

- [ ] **P1 旧 pending 不复活**：用 DevTools 暂时占满 `storage.local` 配额，关闭一个标签使写入失败（页脚出现“有 1 条…尚未保存”）；释放空间前清空普通最近关闭；恢复空间并等待补写/重启 worker，旧记录不得重新出现。
- [ ] **P2 旧事件不覆盖新事件**：在 P1 基础上让同一 URL 先失败、后成功关闭；旧事件晚补写时，标题/时间/置顶顺序仍为较新一次。
- [ ] **P3 删除后 pending 取消**：单删某 URL 时存在同 URL pending，删除后补写不得恢复；之后真实关闭该 URL 仍可生成新条目。

- [ ] **R2** 无痕窗口点击工具栏图标：只显示本次无痕数据；普通历史不泄漏。
- [ ] **R3** 关闭弹窗（不是关闭窗口）不触发无痕清理；只有关闭最后一个无痕窗口才清理。
